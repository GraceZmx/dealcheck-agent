说明：
- 成本按高峰时段价格计算（保守）。思考 token 计入成本，本次关闭了思考模式，所以为 0。4 次模型调用中，3 次是 Agent，1 次是邮件。
- 约一半的输入 token 命中了缓存（多轮对话共享前缀），所以实际成本比"全部未命中"的估算更低。
- 耗时包含邮件生成；Agent 第一轮通常会并行发出两次搜索。
- 5 个案例都没有调用 `fetch_page`：搜索摘要已经够用。
- 和 PRD 13.3 节的目标对比：单次成本 ¥0.043，远低于 ¥2.00 的上限；P90 耗时约 12 秒，远低于 90 秒的上限。

## 观察到的问题（留到 M3 / M4 处理）

1. 来源 URL 带有跟踪参数和 `#1` 之类的片段，展示前应当清理。
2. 因为 HR-8 而降为"谈判"、但条款和报价都没有问题的案例，邮件只能泛泛地说"想聊聊细节"，因为按规则邮件不能提及品牌调查的结论。界面上应当提示用户：先自行核实，再决定是否回复。
3. 同一份文档的不同片段可能被登记成多个来源（例如同一个 PDF 的 `#1`、`#5`），导致独立来源数看起来更多。不过独立来源是按域名计算的，不影响 HR-2 的判定。
